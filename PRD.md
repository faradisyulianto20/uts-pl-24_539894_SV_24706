Feature Specifications### 3.1 Authentication & Authorization Subsystem1. **Manual Auth:** Register (`name`, `email`, `password`, `password_confirmation`) dan Login (`email`, `password`).2. **OAuth Google (Socialite):** Login 1-click menggunakan Google. Menggunakan endpoint redirect dan callback untuk menukarkan authorization code menjadi Sanctum Bearer Token.3. **Token Management:** Menggunakan **Laravel Sanctum**. Setiap request terotentikasi wajib menyertakan header `Authorization: Bearer <token>`.4. **Strict Token Enforcement (Soal 1a):** Seluruh endpoint API selain `/api/register`, `/api/login`, dan `/api/auth/google/*` diwajibkan melewati middleware `auth:sanctum`. Jika token tidak ada/invalid, API mengembalikan HTTP status `401 Unauthorized`.### 3.2 Blog Post Management (CRUD dengan Image Upload)1. **Create:** Admin menambahkan postingan baru berisi data teks (`title`, `content`, `published_at`, `is_popular`) dan file media opsional (`cover_image`).   - **Request Type:** `multipart/form-data`.   - **Processing:** Backend memvalidasi berkas gambar (`mimes: jpg, jpeg, png`, `max: 2048` KB), menyimpannya di `storage/app/public/posts`, dan menyimpan relative path ke basis data.   - **Status HTTP saat berhasil:** `201 Created`.2. **Read (List & Detail):** Menampilkan seluruh postingan (dengan pagination) dan detail artikel tunggal beserta komentar terikat.   - **Image Rendering:** Endpoint mengembalikan atribut full URL dari `cover_image` (misal `http://localhost:8000/storage/posts/...`) sehingga frontend Vue dapat langsung merendernya via tag `<img :src="post.cover_image_url" />`.3. **Update:** Admin memperbarui judul, isi, status populer, serta opsi mengganti file `cover_image` yang sudah ada.   - **Laravel Multipart Handling:** Karena keterbatasan PHP pada method `PUT` dengan `multipart/form-data`, request update menggunakan `POST /api/posts/{id}` dengan field `_method=PUT`.   - **Status HTTP:** `200 OK`.4. **Delete:** Admin menghapus postingan (beserta file gambar fisik yang terkait dari disk penyimpanan). Status HTTP: `200 OK`.5. **Validation Error Handling:** Validasi form input mengembalikan HTTP status `422 Unprocessable Entity` beserta pesan error JSON terstruktur.### 3.3 Comment Subsystem1. **List Comments:** Menampilkan komentar pada detail postingan.2. **Create Comment:** User/Admin terautentikasi dapat menambahkan komentar pada postingan tertentu.3. **Delete Comment:** Admin dapat menghapus komentar spam/tidak pantas.### 3.4 Public UI & Admin Dashboard (Vue 3)1. **Public Blog View:** Tampilan bertema *literary blogspot*, menyajikan artikel utama lengkap dengan cover image, sidebar "Postingan Populer", dan section komentar. Layout menerapkan struktur **2-kolom** (main content + sidebar).2. **Admin Dashboard View:** Panel khusus admin berisi statistik ringkas (total posts, total comments, total views), tabel data postingan dengan thumbnail cover, aksi edit/hapus, serta form tambah/edit dengan area upload cover image yang menampilkan preview terpisah (empty state vs uploaded/preview state).---## 4. tanggal publikasi, views), konten artikel dengan tipografi yang nyaman dibaca, serta **CommentSection** (avatar, nama pengguna, waktu komentar, isi komentar, form tambah komentar untuk user terautentikasi).2. **Profile Page:** Halaman profil untuk user terautentikasi untuk melihat dan memperbarui data diri (nama, email, avatar) dengan preview avatar.3. **Admin Comments Page:** Halaman moderasi komentar global (seluruh komentar di sistem) dengan informasi post terkait, penulis, isi komentar, tanggal, serta aksi hapus komentar.4. **Admin Settings Page:** Halaman pengaturan admin sesuai desain (minimal/placeholder) dengan dukungan tema Light/Dark.### 3.5 UI/UX Design System1. **Theme System:** Mendukung **Light Mode dan Dark Mode** dengan CSS Variables (design tokens) untuk warna, background, surface, border, teks, dan komponen. Tema disimpan di localStorage dan dapat diubah melalui Theme Toggle pada Navbar.2. **Typography & Layout:** Menggunakan tipografi yang konsisten, layout responsif, serta struktur 2-kolom pada halaman blog publik.3. **Cover Image Upload UX:** Pada form tambah/edit postingan (Dashboard/Admin), area upload menampilkan **preview terpisah** antara kondisi kosong (*empty state*) dan kondisi telah memilih/memiliki gambar (*uploaded/preview state*). Mendukung mengganti (*replace*) gambar cover saat melakukan update.4. **Components:** Tersedia komponen reusable seperti Navbar.vue, SidebarPopular.vue, CommentSection.vue (dan komponen pendukung lain sesuai kebutuhan desain).### 4.1 Additional API Endpoints (Design Alignment)Untuk mendukung halaman Profile dan Admin Comments sesuai desain, ditambahkan endpoint berikut (dapat diimplementasikan selaras dengan arsitektur Sanctum):| Method | Endpoint | Access | Function | Content-Type | Expected HTTP Status || --- | --- | --- | --- | --- | --- || GET | /api/me | Token | Mendapatkan informasi user yang sedang terautentikasi | None | 200 OK, 401 Unauthorized || PUT/PATCH | /api/me | Token | Memperbarui profil user sendiri (nama, email, avatar).
